Which pages are quietly losing ground — and which ones are worth saving?

A refresh-opportunity model that ranks content by decline risk, tested against a simple staleness rule, on 30,000 anonymized pages.

01Abstract

Content teams need a way to tell which pages are declining before traffic disappears, without reviewing every page by hand. This project asks whether a learned model can rank pages by decline risk more precisely than a simple staleness-and-visibility rule. Using 30,000 anonymized content records with pre-decision signals only, a Random Forest classifier was trained to predict a 90-day decline label and validated on a held-out test split. The model reached 0.90 precision in its top 20 ranked pages, against 0.50 for the hand-written baseline on the same split. The result is a ranked action list — pages flagged Improve, Protect, Rewrite, or Monitor — with the reasoning behind each flag, so a content team can prioritize review time toward the pages most likely to be slipping.

02Introduction

Search content decays quietly. A page can hold its position for months and then slide — losing impressions, clicks, and revenue — long before anyone notices, because nobody is checking all of it at once. Large content libraries make manual review impractical: a team reviewing every page on a fixed schedule spends the same attention on pages that are fine as on pages that are actively failing.

The decision this work supports is simple to state and hard to do by hand: given a library of pages, which ones should a content team look at first? A ranking that reliably puts declining pages near the top turns an unbounded review task into a short, prioritized list. This capstone builds that ranking, compares it honestly against a rule a human would write by hand, and turns the result into a reusable action playbook.

03Data

The analysis uses the anonymized content-refresh release shipped with the FlyRank ML Internship starter repository — content_refresh_anonymized.csv — which contains 30,000 content records across pseudonymized clients. Each row describes one piece of content with 45 fields, including content age, time since last update, 90-day impressions, average search position, click-through rate, word count, and a trend label describing whether performance moved up, down, or stayed stable over the observed window.

No client names, domains, URLs, or raw queries appear anywhere in this dataset or in this write-up. All identifiers are hashed content and client IDs, consistent with the public-safe handling required for this work.

What was excluded, and why

  • Rows with missing core signals were kept but imputed to zero for tree-based modeling rather than dropped, since Random Forests handle sparse signal reasonably and dropping rows would bias the sample toward older, more complete content.
  • trend_pct was deliberately excluded from every modeling feature set. It is the exact percentage change the decline label is derived from, so including it would let the model read the answer directly rather than learn from independent signals — see Methodology below.
  • Product-generated decision flags (health scores, "needs review" tags, and similar fields) are not present in this release in the first place, which keeps every feature honestly pre-decision.

04Methodology

Label definition

The target is binary: a page is labeled declining (1) when its recorded trend direction is "down," and not declining (0) otherwise. Across the full dataset, 54.2% of pages carry the declining label — a fairly balanced split, which is one reason class-balanced weighting was used rather than resampling.

Features

Six pre-decision signals were used for every model in this report: content age in days, days since last update, 90-day impressions, average search position, click-through rate, and word count. Each of these is knowable before any human or system decides a page is declining — none of them encode the outcome itself.

Baseline: a rule a person would write

Before modeling, a hand-written rule was defined as the comparison point: a page is worth reviewing if it is stale (no update in 180+ days) and visible (500+ impressions in the last 90 days), scored by how much exposure it carries. This mirrors how a content team would triage manually — it's a reasonable, legible starting point, not a strawman.

Validation design

Data was split 75/25 into train and test sets with stratification on the label, using a fixed random seed for reproducibility. The model never sees test-set rows during training. Both the learned model and the hand-written baseline are scored on the identical held-out test rows, so the comparison in the Results section is apples-to-apples rather than the model being evaluated on easier data.

Leakage check

Why trend_pct is excluded: this field is the exact percentage change the decline label is computed from. Feeding it into the model as a feature was tested deliberately during development and produced near-perfect precision — a clear sign the model was reading the answer rather than learning a pattern. The rule applied throughout this project: if a feature would only be known because someone already made the decision being predicted, it is left out.

Model

A Random Forest classifier (200 trees, max depth 6, balanced class weights) was trained on the six pre-decision features. Random Forest was chosen over a single decision tree because a single shallow tree can only express a handful of distinct scores, which compresses too many pages into tied ranks to produce a usable priority order at scale.

06Limitations & honest framing

  • Observed, not causal. This model reports association between signals and decline, not why a page declines. A high decline-risk score is a prompt to review a page, not a diagnosis of what's wrong with it.
  • Single time window. The dataset reflects one snapshot period. Whether these same features carry the same importance across seasons or content categories has not been tested here and would need a rolling evaluation.
  • In-sample scoring for the action list. The ranked recommendations in Section 07 score every page, including rows the model trained on. The precision numbers in Section 05 are the honest, held-out figures — the action list itself is a deployment artifact, not a second evaluation.
  • No client-holdout split performed in this pass. The 75/25 split is row-level, not grouped by client. If a small number of clients dominate the "declining" class, some of the model's apparent skill could be client-specific pattern-matching rather than a signal that generalizes to a completely new client. This is the single most important next check before trusting the model in production, and is flagged explicitly rather than glossed over.
  • Decision-support, not decision-making. The Improve / Protect / Rewrite / Monitor labels are a starting triage, not a replacement for editorial judgment about a specific page.

07Ranked recommendations

Every page was scored for decline risk and assigned to one of four actions based on its risk score combined with current visibility and staleness:

239

150

5

The Improve group is the priority queue: 274 pages that are both at high statistical risk of decline and still carrying meaningful search visibility, meaning there's an audience left to recover before it disappears. A content team should work this list top-down, ordered by impressions, since every additional day of decay costs more of the traffic that's still there. The highest-exposure page in this group alone carries over 26,000 90-day impressions at a 5% click-through rate — a page clearly still being served in results, but converting very few of those impressions into clicks, and now flagged as trending down.

Playbook: Improve → editorial refresh this week, prioritized by impressions. Protect → no action, re-check next cycle. Monitor (low visibility) → batch review monthly, not urgent. Rewrite → structural rebuild, these pages are stale enough that a refresh alone is unlikely to help.
